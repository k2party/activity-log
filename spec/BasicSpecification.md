## 1. システム概要

### 1.1 目的

睡眠・食事・服薬・外出などの日々の行動と「1日の感想」を記録し、週間帳票（PDF）・CSV として出力する。
本人が日々の生活を振り返るとともに、帳票を支援者・医療機関などに提示できるようにする。

### 1.2 利用者と権限

| 利用者 | 説明 | できること |
| --- | --- | --- |
| 一般ユーザー | 管理者が登録した利用者 | 自分の行動記録・感想の入力・編集・削除、PDF / CSV 出力、自分のパスワード変更、自分の Gemini API キーの登録・削除、感想の AI 要約 |
| 管理者 | ユーザID `admin`（固定・削除不可） | ユーザーの追加・氏名変更・パスワード再設定・削除、任意のユーザーの PDF / CSV 出力（記録の入力・編集はしない） |

### 1.3 機能一覧

| No | 機能 | 概要 | 利用者 |
| --- | --- | --- | --- |
| F01 | ログイン / ログアウト | ユーザID・パスワードで認証し、セッション Cookie を発行する | 全員 |
| F02 | パスワード変更 | 自分のパスワードを変更する（他端末のセッションは無効化） | 全員 |
| F03 | 行動記録の入力 | 種類を選び、日付・開始・終了時刻・メモを入力して記録する | 一般 |
| F04 | 睡眠・起床の記録 | 就寝を記録し、起床時に同じ記録へ終了時刻を入れる | 一般 |
| F05 | 行動記録の一覧・編集・削除 | 1日 / 期間で記録を表示し、行単位で編集・終了入力・削除する | 一般 |
| F06 | 1日の感想 | 日付ごとに1件の感想を入力・編集・削除する | 一般 |
| F07 | 感想の AI 要約 | 入力中の感想を Google Gemini で要約して入力欄に反映する | 一般（API キー設定済みのみ） |
| F08 | Gemini API キー設定 | 自分の API キーを暗号化して登録・削除する | 一般 |

| F10 | 週間帳票 PDF 出力 | 指定期間を含む月〜日を A4 横1ページの帳票として出力する | 全員（管理者は対象ユーザーを選択） |
| F11 | CSV 出力 | 表示中の期間の記録を CSV で保存する | 全員（管理者は対象ユーザーを選択） |
| F12 | ユーザ管理 | ユーザーの一覧・追加・変更・削除、API キー設定状態の確認 | 管理者 |

| F15 | 管理者マニュアル | 管理者向けのマニュアル（HTML）をダウンロードさせる | 管理者 |

## 2. システム構成

### 2.1 方針

- サーバーは **Python 標準ライブラリのみ**で実装する（外部パッケージを使わない）。
- データは **SQLite**（1ファイル）に保存する。
- フロントエンドはビルド工程の無い素の HTML / CSS / JavaScript（各画面1ファイル、JS はインライン）。
- PDF はライブラリを使わず自前で組み立てる。
- 外部サービスは、AI 要約で使う Google Gemini API のみ。

### 2.2 構成図

```
 ブラウザ（PC / スマートフォン）
   │  HTTPS
   ▼
 リバースプロキシ（ホスト OS の nginx 等）
   │  HTTP  127.0.0.1:8000
   ▼
 ┌─────────── コンテナ（Docker / Podman Pod「diary」）───────────┐
 │  app/server.py（ThreadingHTTPServer）                         │
 │    ├ auth.py        認証・セッション・ログイン試行制限         │
 │    ├ pdf_report.py  週間帳票 PDF 生成                          │
 │    ├ summarize.py   Gemini API 呼び出し ───────────────┐      │
 │    └ secretbox.py   API キーの暗号化                    │      │
 │  /data/activity_log.db（SQLite・名前付きボリューム）     │      │
 └──────────────────────────────────────────────────────────┼──────┘
                                                            ▼ HTTPS
                                          Google Gemini API（generativelanguage.googleapis.com）
```

### 2.3 モジュール構成

| ファイル | 役割 |
| --- | --- |
| `app/server.py` | HTTP サーバー、ルーティング、API、入力チェック、DB スキーマ定義・マイグレーション |
| `app/auth.py` | パスワードハッシュ（PBKDF2）、セッショントークン、ログイン試行制限 |
| `app/pdf_report.py` | 週間帳票 PDF の生成（PDF 書き出し・レイアウト・睡眠の属する日の判定） |
| `app/summarize.py` | Gemini API による感想の要約、呼び出し回数制限 |
| `app/secretbox.py` | Gemini API キーの可逆暗号化（HMAC-SHA256 による CTR＋改ざん検知） |
| `app/index.html` | 行動記録画面（入力・一覧・感想・PDF / CSV 出力・各種設定ダイアログ） |
| `app/login.html` | ログイン画面 |
| `app/users.html` | ユーザ管理画面 |
| `app/MANUAL.html` | 一般ユーザー向けの利用マニュアル（`/manual.html` で配布） |
| `app/MANUAL_ADMIN.html` | 管理者向けマニュアル（`/manual_admin.html` で配布。管理者のみ） |

### 2.4 実行環境

| 項目 | 内容 |
| --- | --- |
| 言語 | Python 3（コンテナは `python:3.14-slim`） |
| DB | SQLite 3（`PRAGMA foreign_keys = ON`） |
| 実行形態 | 直接起動 / Docker Compose / Podman Quadlet（rootless） |
| 公開 | `127.0.0.1:8000` のみ。外部からはリバースプロキシ経由 |
| 実行ユーザー | コンテナ内は非 root（UID 10001） |
| 対応ブラウザ | `<dialog>`・Fetch API・Clipboard API に対応した最新ブラウザ（PC / スマートフォン） |

### 3.2 画面遷移

```

   ▲                       │  ├─「Gemini設定」→ D01                       │
```

### 3.3 G01 ログイン

- 入力：ユーザID、パスワード。
- 成功時は `/` へ遷移する。管理者が初期パスワードでログインした場合は、G02 にパスワード変更を促す通知を出す（`sessionStorage` に記録）。
- 失敗時はエラーメッセージを表示する。失敗が続いた場合は一時的に拒否する（6.3 参照）。
- フォームの下に「利用マニュアルをダウンロード」のリンクを置く。

### 3.4 G02 行動記録（一般ユーザー）

| 領域 | 内容 |
| --- | --- |
| ヘッダ | 氏名（ユーザID）、「Gemini設定」「パスワード変更」「マニュアル」（利用マニュアルのダウンロード）「ログアウト」。管理者のみ「ユーザ管理」「管理者マニュアル」 |
| 入力カード | 種類ボタン（🌙睡眠 / 🍚食事 / 💊服薬 / 🚶外出 / 📝その他）、日付、開始時刻、終了時刻、メモ、「〇〇を記録」ボタン |
| 表示切替 | 「1日」/「期間」タブ、前後移動、日付（期間は開始〜終了）、プリセット（今日・昨日・今週・過去7日・今月・先月） |
| 出力 | 「PDF出力」（別タブで表示）、「CSV出力」（ダウンロード） |
| 一覧 | 日ごとに 開始 / 終了 / 時間 / 行動（種類バッジ＋メモ）/ 操作（起床・終了、編集、削除）と、日の合計時間 |
| 1日の感想 | 日ごとの感想欄（入力・編集・保存・取消、AI 要約・元に戻す） |

#### 入力フォームの仕様

| 種類 | 開始ラベル | 終了ラベル | メモ欄 | メモの候補ボタン |
| --- | --- | --- | --- | --- |
| 睡眠 | 就寝時刻 | 起床時刻（任意） | なし | — |
| 食事 | 開始時刻 | 終了時刻（任意） | メモ | 朝食・昼食・夕食・間食 |
| 服薬 | 服薬時刻 | なし | メモ | 朝食後・昼食後・夕食後・就寝前 |
| 外出 | 出発時刻 | 帰宅時刻（任意） | 行先 | — |
| その他 | 開始時刻 | 終了時刻（任意） | 内容 | — |

- **時刻入力**：`00:00`〜`47:59`。`9:30`・`0930`・`930`・`9`・`25:00`・全角数字・「時」「分」表記を受け付けて `HH:MM` に正規化する。24時以降は翌日として扱う。
- **終了時刻**：開始より後で最初に来るその時刻とする（例：開始 23:30・終了 7:00 → 翌 7:00）。開始と同じ時刻（24時間後）はエラー。24時間を超える記録は一覧の編集で日時を指定する。
- **「今」ボタン**：入力欄の日付を基準にした現在時刻を入れる（昨日の日付なら `25:30` のように24時以降で入る）。
- **入力ヒント**：開始・終了の下に、換算結果（「= 前日 23:30」「→ 翌07:00（7時間30分）」など）やエラーを表示する。
- **メモ**：20文字まで。食事・外出・その他は過去の入力から候補（datalist）を出す。
- 種類を切り替えても、日付・時刻・メモの入力値は引き継ぐ（睡眠中の起床入力に切り替わる場合を除く）。

#### 睡眠・起床の入力

- 睡眠ボタンで就寝を記録すると、起床時刻が未入力の睡眠になる。
- 起床未入力の睡眠があり、就寝から48時間以内なら「睡眠中」とし、入力カードに「😴 睡眠中：（就寝日時）〜（経過時間）」を表示する。
- 睡眠中に睡眠ボタンを押すと「起床を記録」モードになる。就寝は記録済みの値、起床は現在時刻が入り、送信すると記録済みの睡眠の終了時刻を更新する。
- 就寝を記録するとき、18:00 以降なら日付は翌日（その睡眠が属する日）を既定にする（5.1 参照）。

#### 一覧の表示

- 「1日」表示は記録が無くても表示する（感想を入力できるように）。「期間」表示は、記録・参考表示・感想のいずれかがある日だけ表示する。
- 各行の時刻は、その日の 0:00 を基準に「前日 23:30」「翌07:00」のように表示する。
- 別の日に属するが、その日にかかっている記録（日をまたぐ外出、翌朝起床の睡眠の就寝など）は、参考行として「（m/d に計上）」付きで表示する。参考行はその日の合計に含めない。
- 終了が未入力の行には「終了」（睡眠は「起床」）ボタンを出す。睡眠中の行は終了欄に「睡眠中」、時間欄に経過時間を出す。
- 編集は行内で行う（種類・日付・開始・終了・メモ）。削除は確認後に行う。
- 1分ごとに再描画する（睡眠中の経過時間の更新など）。編集中・感想入力中は再描画しない。

#### 1日の感想

- 1000文字まで。空にして保存すると削除する。
- 「1日」表示で未入力の日は、最初から入力欄を表示する。
- 入力中の内容は再描画しても保持する。
- 「AI要約」ボタンは Gemini API キーを設定済みのユーザーにのみ表示する（未設定のユーザーには要約手段を提供しない）。
  - 50文字以上の入力中の本文を要約し、入力欄を要約結果で置き換える（保存はしない。利用者が確認して保存する）。
  - 要約前の本文は「元に戻す」で復元できる。
  - 要約中に本文が書き換えられた場合は、要約結果を反映しない。
  - エラーは感想欄の直下に表示する。

### 3.5 G02 行動記録（管理者）

- 入力カード・一覧・「Gemini設定」を非表示にし、「出力するユーザー」の選択欄を表示する（管理者自身は選択肢に含めない）。
- 期間を指定し、選択したユーザーの PDF / CSV を出力する。一覧の代わりに「（氏名）の（期間）の記録：n件」を表示する。

### 3.6 D01 Gemini 設定

- 現在のキーの状態（「設定済み（…末尾4文字）」/「未設定」）を表示する。
- API キーを入力して保存すると登録（上書き）する。「キーを削除」で削除する（確認あり）。
- キーの入力欄はパスワード形式で、登録済みのキーの値は表示しない。

### 3.7 D02 パスワード変更

- 現在のパスワード、新しいパスワード（8〜128文字）、確認用を入力する。
- 変更すると、同じユーザーの他の端末のログインは無効になる。

### 3.8 G03 ユーザ管理

| 領域 | 内容 |
| --- | --- |
| ヘッダ | 「管理者マニュアル」（管理者マニュアルのダウンロード）、「行動記録に戻る」 |
| ユーザー追加 | ユーザID（半角英数字と `_ . @ -`、32文字以内、登録後は変更不可）、氏名（50文字以内）、パスワード（8〜128文字） |
| ユーザー一覧 | ユーザID（管理者は「管理者」タグ）、氏名（編集可）、新しいパスワード（変更時のみ入力）、Gemini API キーの状態、保存・削除ボタン |

- Gemini API キーの状態表示：

  | API の値 | 表示 | 意味 |
  | --- | --- | --- |
  | `set` | `...abcd`（末尾4文字） | 設定済み |
  | `unset` | 未設定 | 未登録 |
  | `nosecret` | 使用不可 | 登録はあるが、サーバーに秘密鍵（`GEMINI_KEY_SECRET`）が無い |
  | `invalid` | 要再登録 | 秘密鍵が変わったなどで復号できない（本人が再登録すると使える） |

- 管理者は API キーの値を見ること・登録・変更することはできない（本人のみ）。
- パスワードを変更すると、対象ユーザーのログインは無効になる（再ログインが必要）。
- 削除は確認後に行い、そのユーザーの行動記録・感想・セッションもすべて削除する。管理者は削除できない。

## 4. 帳票・ファイル出力設計

### 4.1 週間帳票 PDF

| 項目 | 内容 |
| --- | --- |
| 用紙 | A4 横 |
| 単位 | 1週（月曜〜日曜）＝1ページ。指定期間を含むすべての週を出力する |
| ヘッダ（1行） | 左：「行動記録（yyyy/m/d～m/d）　氏名：（氏名）」（年をまたぐ週は終了日にも年を付ける）。右：「出力日：yyyy/mm/dd HH:MM:SS」（日本時間） |
| フッタ | ページ番号「n / 総ページ数」 |
| 列 | 日付 / 時刻（FROM〜TO）/ 行動 / メモ / 1日の感想 / 服薬時刻 |
| フォント | PDF 標準の日本語フォント「平成角ゴシック W5」を参照（埋め込まない） |
| 表示方法 | `Content-Disposition: inline`（ブラウザの別タブで表示） |

- **日付**：「m/d（曜）」。土曜は青、日曜は赤。日ごとに背景色を交互にする。
- **時刻**：その日を基準に「23:30 〜 翌07:00」「前日23:30 〜 06:45」。終了が未入力なら「23:30 〜」。
- **メモ**：睡眠はメモの代わりに睡眠時間（「7時間30分」。起床が未入力なら空欄）。列幅を超える場合は末尾を「…」で省略する。
- **1日の感想**・**服薬時刻**：日ごとに縦に結合したセルに上詰めで表示する。感想は折り返す。服薬は行動の行には出さず、服薬時刻の列に「HH:MM メモ」で並べる。
- 記録の無い日は「記録なし」と表示する。
- 1週が1ページに収まるよう、文字サイズを 9.5pt〜5.0pt の範囲で自動調整する。最小でも収まらない場合のみ、日単位で改ページする（見出しに「（1/2）」などを付ける）。
- BMP 外の文字（絵文字など）は「〓」に置き換える。

### 4.2 CSV

| 項目 | 内容 |
| --- | --- |
| 生成場所 | ブラウザ（クライアント側で生成） |
| 対象 | 表示中の期間に属する記録（属する日は 5.1 の規則） |
| 文字コード | UTF-8（BOM 付き）、改行 CRLF、全項目をダブルクォートで囲む |
| 列 | 日付（属する日）/ 種類 / 開始日時 / 終了日時 / メモ |
| 並び順 | 日付 → 開始日時 → ID |

- 睡眠のメモ列は睡眠時間（帳票と同じ。起床が未入力なら空欄）。
- 感想は CSV には含めない。

| 出力 | ファイル名 |
| --- | --- |
| PDF | `行動記録_開始日_終了日_出力日時.pdf`（日本語を扱えない環境向けに `activity_log_…pdf` も指定） |
| CSV | `行動記録_開始日_終了日_出力日時.csv`（開始日＝終了日なら `行動記録_日付_出力日時.csv`） |

- 日付は `YYYY-MM-DD`、出力日時は日本時間の `YYYYMMDD-HHMMSS`（PDF はサーバー、CSV は端末の時計）。
- 管理者が他のユーザーを出力した場合は、「行動記録_」の後にユーザIDを入れる。
- 出力ごとに別名にするのは、Android などで同名の古いダウンロード済みファイルが開かれるのを避けるため。

## 5. 業務ルール

### 5.1 睡眠の「属する日」

睡眠は日をまたぐことが多いため、記録を表示・集計する日（属する日）を次のように決める。

| 条件 | 属する日 | 例 |
| --- | --- | --- |
| 就寝が 18:00 より前 | 就寝した日 | 11/3 01:00 就寝 → 11/3、11/3 13:00 の昼寝 → 11/3 |
| 就寝が 18:00 以降で、起床が未入力または翌日以降 | 就寝の翌日 | 11/2 23:30 就寝 → 11/3 |
| 就寝が 18:00 以降で、起床が当日 24:00 より前 | 就寝した日 | 11/3 19:00〜21:00 の仮眠 → 11/3 |
| 睡眠以外 | 開始した日 | — |

- 一覧・PDF 帳票・CSV はすべてこの基準日で一致させる。判定は `pdf_report.py` の `belongs_date`（サーバー）と `index.html` の `belongsDate`（`SLEEP_DAY_START`）の両方に実装しており、変更時は両方を合わせて修正する。
- 期間の記録を取得するときは、期間の前日 18:00 以降に就寝した睡眠も含めて取得する。
- 入力フォームの日付は「睡眠が属する日」として扱う（例：日付 11/5・就寝 23:30 → 実際の就寝は 11/4 23:30）。

### 5.2 行動記録の入力チェック

| 項目 | ルール |
| --- | --- |
| 種類 | `sleep` / `meal` / `medicine` / `out` / `other` のいずれか |
| 開始日時 | `YYYY-MM-DD HH:MM` 形式で実在する日時（必須） |
| 終了日時 | 未入力可。入力時は開始より後。服薬は常に無し（送られても無視） |
| メモ | 20文字以内（前後の空白は除去）。睡眠は常に空 |

### 5.3 その他の制約

| 項目 | ルール |
| --- | --- |
| 期間指定 | `from` ≤ `to`、最大400日（両端含む） |
| 1日の感想 | ユーザー×日付で1件、1000文字以内。空で保存すると削除 |
| ユーザID | 半角英数字と `_ . @ -`、1〜32文字。大文字小文字を区別せず重複不可。変更不可 |
| 氏名 | 1〜50文字 |
| パスワード | 8〜128文字 |
| Gemini API キー | 空白を含まない印字可能 ASCII、10〜200文字 |
| AI 要約 | 対象は 50〜1000文字。1ユーザーあたり10分間に20回まで |

## 6. セキュリティ設計

### 6.1 認証

- パスワードは PBKDF2-HMAC-SHA256（16バイトのソルト、600,000回）でハッシュ化して保存する。
- 存在しないユーザIDでもダミーのハッシュ計算を行い、応答時間からユーザIDの存在を推測されないようにする。
- 初期管理者 `admin` / `actAdmin` は DB 作成時に自動で作成する。初期パスワードのままログインすると変更を促す。

### 6.2 セッション

| 項目 | 内容 |
| --- | --- |
| トークン | `secrets.token_urlsafe(32)` |
| 保存 | Cookie `alog_session` にトークン、DB にはその SHA-256 ハッシュのみ |
| Cookie 属性 | `HttpOnly`、`SameSite=Lax`、`Path=/`。HTTPS 時（`COOKIE_SECURE=1` またはプロキシの `X-Forwarded-Proto: https`）は `Secure` |
| 有効期限 | 最終アクセスから14日（アクセスのたびに延長） |
| 無効化 | ログアウト、本人のパスワード変更（他端末分）、管理者によるパスワード再設定（対象ユーザー分）、ユーザー削除 |

### 6.3 ログイン試行制限

- 接続元 IP＋ユーザID（小文字化）ごとに、15分間に5回失敗すると一時的にログインを拒否する（HTTP 429）。
- 状態はメモリ上に持つ（再起動でリセット）。

### 6.4 CSRF 対策

- 更新系リクエスト（POST / PUT / DELETE）は `X-Requested-With: fetch` ヘッダーが無ければ 403 とする。
- Cookie は `SameSite=Lax`。

### 6.5 アクセス制御

- 行動記録・感想の更新は、ログイン中のユーザー自身のものに限る（`user_id` 条件付きで更新）。
- 閲覧・出力系 API（行動記録一覧・感想一覧・PDF）は、管理者に限り `user_id` で他のユーザーを指定できる。
- ユーザ管理 API は管理者のみ（403）。

### 6.6 Gemini API キーの保護

- API キーは `secretbox.py` で暗号化して `users.gemini_api_key` に保存する。
  - 暗号化：HMAC-SHA256 を擬似乱数関数とする CTR 方式（16バイトの nonce）。
  - 改ざん検知：HMAC-SHA256（Encrypt-then-MAC、32バイトのタグ）。
  - 鍵：環境変数 `GEMINI_KEY_SECRET`（32文字以上）から HKDF と同じ手順で暗号用鍵・認証用鍵を導出する。
  - 関連データにユーザIDを入れ、暗号文を他のユーザーの行にコピーしても復号できないようにする。
  - 保存形式：`v1:` ＋ base64url（nonce ‖ 暗号文 ‖ タグ）。
- 画面・API にはキー本体を返さず、設定の有無と末尾4文字だけを返す。
- 秘密鍵は DB と別に管理する（Podman では secret `diary-gemini-key-secret`）。秘密鍵を変更・紛失すると、登録済みのキーは復号できず「未設定」（ユーザ一覧では「要再登録」）扱いになる。
- `GEMINI_KEY_SECRET` が未設定の場合、API キーの登録と AI 要約は使えない（他の機能は使える）。
- Gemini API のエラーの詳細はサーバーログにのみ出し、画面には一般的なメッセージを出す。

### 6.7 その他

- 応答に `Cache-Control: no-store`、`X-Content-Type-Options: nosniff` を付ける。画面には `X-Frame-Options: DENY`、`Referrer-Policy: same-origin` も付ける。
- 画面に表示する利用者の入力値は HTML エスケープする。
- リクエストボディは 1MB まで。
- リバースプロキシ配下（`TRUST_PROXY=1`）では `X-Forwarded-For` の先頭を接続元 IP とする。
- サーバーは `127.0.0.1` のみに公開し、外部からはリバースプロキシ（HTTPS）経由で接続する。

## 7. 外部連携設計（Google Gemini API）

| 項目 | 内容 |
| --- | --- |
| 用途 | 1日の感想の要約 |
| エンドポイント | `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` |

  | 状況 | 応答 | 画面のメッセージ（要旨） |

  | 接続できない | 502 | 要約サービスに接続できない |
  | 応答が空（ブロック等） | 502 | 要約を生成できない |

- 感想の本文は Google に送信される（Gemini 設定画面で利用者に明示する）。

### 8.3 スキーマのバージョン管理

- `PRAGMA user_version` でバージョンを管理し（現在 7）、起動時に自動で移行する。
- DB のバージョンがプログラムより新しい場合は起動しない。

| 移行 | 内容 |
| --- | --- |
| 0〜1 → 7 | 旧 `entries` テーブルを削除して新規作成（データは引き継がない） |
| 2・3 → 4 | ユーザー・ログイン機能を追加。既存の行動記録は `admin` の記録として引き継ぐ |
| 4 → 5 | 種類「服薬」を追加（`activities` を作り直してデータを移す）、`daily_notes` を追加 |
| 5 → 6 | `users.gemini_api_key`（平文）を追加 |
| 6 → 7 | `users` を作り直して API キーを暗号化（平文のキーがあるのに `GEMINI_KEY_SECRET` が未設定なら起動を中止）。移行後に VACUUM して平文を残さない |

- CHECK 制約の変更などは、新しいテーブル（`〇〇_new`）を作ってデータを移し、旧テーブルを削除してから RENAME する。

## 11. 制約・前提

- 日時はサーバーのローカル時刻で扱う（タイムゾーン情報は保存しない）。帳票の出力日時・ファイル名の日時は日本時間（JST 固定）。
- PDF はフォントを埋め込まないため、表示は閲覧側の日本語フォントに依存する（Acrobat / Chrome / Edge / macOS プレビュー等で確認）。
- 種類（`CATEGORIES`）は `server.py`・`pdf_report.py`・`index.html` と DB の CHECK 制約にそれぞれ定義があり、追加・変更時はすべてを合わせて修正し、マイグレーションを追加する。
- Docker 用のファイルは `docker/` に集約する（`Dockerfile`・`Dockerfile.dockerignore`・`compose.yaml`・`.env.sample`・`build.sh`）。ビルドコンテキストはリポジトリ直下。
- `docker/Dockerfile` は `app/` をまるごとコピーし、`docker/Dockerfile.dockerignore` は `app/` だけを通す（`__pycache__` は除外）。`app/` に置いたファイルはすべてイメージに入るため、アプリ以外のファイルは置かない。
- 自動テストは無い。動作確認はサーバーを起動してブラウザ / curl で行う。
